# Universal profile template

The signature profile (`universal-profile`, version 1) is registered beside the twenty existing demos. Select Universal in `/v1-1/themes`.

`personalization.js` is the creation-time resolver. It takes a template, onboarding profile, central category metadata and optional page overrides. It returns a JSON-safe snapshot stored in the existing phase-one theme block under `personalization`. Rendering never fetches or reapplies onboarding defaults. The editor changes only page content; draft saving and publishing retain the existing builder endpoints and subscription checks.

Cover candidates use the reviewed Cloudflare category manifest, in order: page URL, exact category, registry parent, optional registry generalCategoryId, neutral brand artwork. The neutral fallback is CSS, requiring no downloaded image. Failed candidates advance through the same list. Avatar candidates are the page/onboarding image, category candidates, then initials. Logo images use contain; creator photos use cover. Category assets retain responsive AVIF/WebP variants and stored focal points. No assets are generated, copied or uploaded by this template.

Actions support kind, platform, label, URL, style and visibility. Invalid or missing destinations are hidden publicly and explained in the editor. WhatsApp uses the saved international number and the existing theme convention of a direct wa.me destination. No fabricated phone number is included. Instagram is initially optional and blank. The social model includes Instagram, TikTok, Facebook, X, YouTube, Telegram, website and email. Category rules provide suggestions only.

The renderer's verified prop defaults false and is never populated from editable page data. A future trusted server integration may supply it; saved page verification fields are ignored.

Future designs can register metadata in the template library and consume the same resolver. Keep account defaults, category registry, category asset manifest, template definitions and page snapshots separate. Future lead templates should retain the existing shared lead-form contract.

Validation: `node --test tests/universal-profile.test.cjs tests/phase-one-b-themes.test.cjs tests/phase-one-b-form.test.cjs tests/category-covers.test.cjs`. Includes ten requested account scenarios plus unsafe URLs, snapshot persistence, badge boundary, responsive R2 sources and legacy theme/form regression checks. Demo preview content is isolated in the preview route and is never used by new page creation.

All new templates should use the shared `ActionIcon` component: real brand SVG icons from react-icons and utility SVG icons from Lucide. Actions may specify an explicit icon ID; legacy actions infer it from platform, kind or label. Do not substitute emoji or text arrows for action icons. Preview-only WhatsApp placeholders show the intended layout without inventing a phone number; public pages still require the saved valid number.

Template covers: every new design must ship with a screenshot of its finished preview displaying the template name. Compress to WebP, upload under versioned `template-covers/<template-id>/` in R2, and set `preview.image`, `preview.width`, `preview.height`, and descriptive `preview.label` in its registry definition. ThemePreview uses this static cover in the picker (lazy loaded, contain crop) and falls back to the live renderer if it fails. Full previews remain interactive personalized renders. Do not use account-specific screenshots or put demo names into saved account pages.

Category descriptions: all 735 entries in the canonical backend category registry expose `defaultDescription`, containing three short lines separated by newline characters. Keep language plain, category-relevant and free of unverified claims. Edit that field to improve individual category copy, then run `node scripts/sync-category-descriptions.cjs` in frontend. The generated lookup lets templates resolve a category from its ID without a runtime fetch. Personalization priority is page override, saved account bio, category description, generic fallback. Existing page snapshots remain unchanged. Three authored lines may wrap into additional visual lines on narrow screens; never clip editable text to force a line count.

Personalized picker cards supersede static marketing covers for universal/versioned templates. `ThemePreview` selects the lightweight `PersonalizedPreview`; `preview.cardLayout: "profile"` explicitly opts into the profile composition. New versioned templates use personalized cards by default. Add a matching lightweight composition when introducing a different design, keeping it free of full renderers, forms and fetches. Use the shared resolved snapshot and ActionIcon. Gallery profile/category requests happen once per mount and instances are memoized. Category card images request the shared 400px WebP URL lazily. Static preview.image is retained for marketing. The full renderer loads on opening the preview dialog. The twenty legacy demos retain their previous previews.

Category CTA defaults: every canonical category has ten ranked `defaultActions`. Rank 1 is Chat on WhatsApp (hot); rank 2 is the relevant category action (hot); ranks 3–9 offer alternatives; rank 10 is optional Follow on Instagram. Each record includes id, label, kind, icon, rank, hot, optional and destinationField, plus platform for social actions. Run `node scripts/sync-category-actions.cjs` after changes. The browser catalog deduplicates definitions. Use `getCategoryActions(category)` for future editors/templates. New pages seed WhatsApp first, one category suggestion and optional social actions; they do not publish all ten. Category-specific URLs come from actionUrls[suggestionId], never an invented booking/shop link. Existing page snapshots and manually reordered actions are preserved.

Rhythm Grid (`rhythm-grid`) uses the same category asset in three media slots (large main tile plus two cropped details). No random cross-category imagery or additional assets are generated. Snapshots reserve media[0..2].url and position for future independent replacement, alongside headline and the single WhatsApp action. The lightweight rhythm card uses the same three 400px category URLs and mosaic composition.

Studio Pass (`studio-pass`) implements the approved full-photo/white-contact-panel concept, not the earlier ticket mockup. The category cover fills the background, brand and category sit in the top header, and the editable headline, saved/category bio and one WhatsApp CTA sit in the white panel. The lightweight `studio` composition mirrors it with lazy 400px imagery. Brand color controls the CTA with computed contrast. Missing imagery uses the existing neutral fallback.
