# MyTikLink redesign strategy

## Shared information architecture

- Home
- Links
- Pages
- Store
- Orders
- Leads
- Analytics
- Tracking
- Help & support
- Settings

Settings contains Profile, Security, Plan & Billing, Tracking, Notifications and Account. Store contains Overview, Products, Orders, Appearance and Store Settings.

## Activation strategy

First login asks one question: what would you like to do first? The options are create an advert page, create a store, create a smart link, or explore. The chosen goal should determine the first recommended action and suppress irrelevant modules.

Home prioritizes attention and recommended work before metrics. New, landing-page, seller and advertiser states use the same component language but different hierarchy.

## Copy principles

- Name the outcome: “Connect TikTok,” not “Configure pixel integration.”
- Name the object: “Add Product,” not “Proceed.”
- Explain technical value before technical detail.
- Confirm exactly what changed and whether work was saved.
- Error messages explain recovery and draft state.

## V2

V2 is the restrained clarity direction. It uses a light navigation shell, flatter grouping, explicit explanations, minimal depth and the fewest competing actions. It optimizes for first-time comprehension and activation.

## V2.1

V2.1 is the premium operational direction. It shares V2's information architecture and copy, then adds a dark workspace anchor, stronger contextual hierarchy, adaptive dashboard states, selective elevation, split-view operations, universal search and richer feedback.

## User simulations

1. A non-technical fashion seller can choose “Create an online store,” add a product through a short guided form, see setup progress, preview, publish and share.
2. A TikTok advertiser can choose an advert page, create it through a goal-led template, then connect TikTok using outcome-based explanations.
3. A creator wanting one smart link sees Links in primary navigation and a three-field Create Link flow.
4. A busy seller can open Orders directly, select an order, review payment and verify it without leaving the workspace.
5. A new user sees what MyTikLink can create before seeing analytics or technical settings.

## Known weaknesses

Public storefront and checkout need their own customer-facing redesign. Product variants, delivery behavior and digital fulfilment must be validated against backend capabilities. Mobile order detail should become a complete sheet in production. Real error states require API-specific testing.
